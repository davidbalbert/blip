An idea from Ori:

Think in terms of duration of regions, not values. Regions are flow-based, not lexical. Consider, open(2), close(2), and read(2):

func open(path string) int in new | error
func read(fd int, buf []byte) int | error
func close(fd int in .) error

`in` denotes a region. `new` is a keyword that represents the start of a new region. The fd was conjured out of thin air. From somewhere global.

Alternatively

func open(path string) int@ | error
func read(fd int, buf []byte) int | error
func close(fd int@) error

Where @ denotes a region (e.g. int@foo). The lack of a region name creates an anonymous region.

When fd is passed to read, it is borrowed because the region isn't passed in. Put another way, because read takes fd without an attached region, read is promising not to escape fd.

    NOTE: I don't think the above totally works. Int is trivially copyable, so it can in fact be escaped. We might need a noesc modifier instead.

Because multiple variables can share a region, you can have multiple variables with the same resource owning value, and can use either of them:

    // ignoring errors for now
    a := open("/tmp/foo.txt")
    b := a

    // b and a have the same region

    read(b) // this is fine
    read(a) // as is this
    read(b) // this is fine too

    close(b) // consumes the region, neither a nor b can be used after this point.

But what about this?

    var a int = 5
    read(a) // ???

If we want to prevent this we need some way of preventing the construction of new file descriptors. But we obviously can't prevent the construction of a new int. So maybe we do this.

    package os

    type Fd struct {
        fd int
    }

    func Open(path string) Fd@ | error
    func Read(fd Fd, buf []byte) int | error
    func Close(fd Fd@) error

Can we come up with a meaningful rule that says you can't make an Fd outside the os package?

Maybe it's you can't create a zero value outside of it's package if it has non-exported fields?

Alternatively, maybe we could find a syntax to get rid of a zero value: i.e. to remove defaults

    type Fd struct {
        fd int = !
    }

Talking in terms of regions lets us unify borrows of normal values and pointers (pointers always have a region because they're always borrowing).

In Ori's version, the Fd returned by Open needs to be consumed (it's linear) because it's annotated with a region. I don't think this is workable. We don't want to have to explicitly drop all pointers that we borrow.

I'm pretty sure we need some other sort of way to say that something must be consumed.

An alternative approach:

func open(path string) int ??? | error
func read(fd int, buf []byte) int | error
func close(fd int esc) error

Fd passed to read doesn't escape (it's not marked as esc), so it's a borrow.

Or the opposite

func open(path string) int ??? | error
func read(fd int noesc, buf []byte) int | error
func close(fd int) error
